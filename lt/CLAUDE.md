# lt/CLAUDE.md

登壇（LT）の発表資料を置くディレクトリ。**ルートの `CLAUDE.md` の必須ルールはここにも掛かる。**
本ファイルはそれに足す固有ルールで、外すためのものではない。

## この配下の位置づけ

- **会場で出した資料の記録**であって、サービス紹介や事例紹介ではない。
- 公開する目的は、サイト本文の能力表示に対して**外部から確認できる裏づけ**を積むこと
  （確認済み事項「AIコンサルティングの根拠」が、公開の裏づけは登壇など外部から
  確認できる活動で補うと定めている）。
- したがって **`index, follow` で公開し、`sitemap.xml` に載せる**。
  `outlook/` の noindex 運用とは方針が逆なので、横断的に見直すときも混同しないこと。

## 固有ルール

### 配色（ルートの `theme.css` 集約ルールの例外）🟡

- **この配下は資料ごとに独自のパレットを持ってよい**（所有者判断 2026-09-12）。
  ルートの規約は「色やテーマ挙動の変更は `theme.css` だけを編集し、各ページには書かない」だが、
  **発表資料は回ごとに作る配布物であり、サイト本体の一部ではない**ため例外とする。
- 常設ページ（`services/nippo-slides.html` など）は引き続き `theme.css` のパレットを使う。
  こちらは例外に含めない。
- レビューで「色が `theme.css` に集約されていない」という指摘が `lt/` 配下に出たら、
  この行を根拠に据え置いてよい。撤回するときはこの行を消す。

### 掲載前の棚卸し 🔴

会場で話したことと、サイトに恒久掲載することは別。**取り込むたびに資料を1枚ずつ確認する。**

1. **受託業務に触れる記述**（客先名・案件の説明における業界名・規模を示す語・
   案件を特定し得る表現）— 必須ルール1。自作の資料であっても、
   **情報の出所が案件なら秘密保持の対象**であることに変わりはない。
   自己紹介は `about.html` の言い回しに揃えるのが安全。
2. **委託元に著作権のある成果物**（要件定義書・設計書・図・画面）— 必須ルール2
3. **契約書の文言・条項番号**— 必須ルール3
4. **数値と出典** — 必須ルール4。**一次資料を読めていない数値は載せない。**
   料金・無料枠のように改定されるものは、**いつ時点のものか**が分かるように書く
   （現在形は現況と誤読される）。
5. **協働先の社名** — 確認済み事項「パートナー企業との協働」の 🔴
6. **第三者の肖像・著作物** — 契約とも自主ルールとも別の、第三者の権利。
   会場で映すことと、サイトに置き続けることは性質が違う。
   **許諾がないものは載せない**（2026-09-12 に1件、埋め込み画像を削除した）。

### 外部リンク

- 資料が拠り所にした**出典へのリンクは残してよい**（必須ルール4は出典を示すことを求めている）。
- ただし **CraftStage の個別イベントページ・代表個人の SNS へのリンクは足さない**
  （確認済み事項「技術コミュニティ CraftStage への関与」の 🔴）。ここは出典ではなく
  裏づけリンクの話なので、上の例外に含めない。
- `target="_blank"` には必ず `rel="noopener"`（ルートの規約・CI が検査する）。

### 会の名前

- **CraftStage は主催団体、AILT会 はその会の名前**（所有者確認 2026-09-12。ルートの
  確認済み事項に記録がある）。**資料が会の名前で書かれているのは表記のずれではない。**
- サイト本文の7箇所は主催団体名で書かれている。**この配下の資料は、その7箇所の
  同期対象には含めない**（関与の書き方ではなく、当日の記録のため）。
