# lt/CLAUDE.md

登壇（LT）の発表資料を置くディレクトリ。**ルートの `CLAUDE.md` の必須ルールはここにも掛かる。**
本ファイルはそれに足す固有ルールで、外すためのものではない。

## この配下の位置づけ

- **会場で出した資料の記録**であって、サービス紹介や事例紹介ではない。
- 公開する目的は、登壇内容を当社の言葉で**記録・公開**すること。
  🔴 **自社サイトに自分で置いた資料は「外部から確認できる裏づけ」にはならない。**
  外部からの確認は connpass のイベントページが担う（確認済み事項「AIコンサルティングの
  根拠」が指しているのはそちら）。この配下のページは当社の自己申告なので、
  **据え置き根拠として「裏づけは積んである」と使わないこと。**
- したがって **`index, follow` で公開し、`sitemap.xml` に載せる**。
  `outlook/` の noindex 運用とは方針が逆なので、横断的に見直すときも混同しないこと。

## 固有ルール

### 配色（ルートの `theme.css` 集約ルールの例外）🟡

- **この配下は資料ごとに独自のパレットを持ってよい**（所有者判断 2026-09-12）。
  ルートの規約は「色やテーマ挙動の変更は `theme.css` だけを編集し、各ページには書かない」だが、
  **発表資料は回ごとに作る配布物であり、サイト本体の一部ではない**ため例外とする。
- 常設ページ（`services/nippo-slides.html` など）は引き続き `theme.css` のパレットを使う。
  こちらは例外に含めない。
- **例外は配色だけに留まらない。** この配下は `theme.css` / `theme.js` を読み込まないため、
  **サイト共通のテーマ切替（`data-theme`）の対象外**になる。資料内で `prefers-color-scheme` まで
  完結させること（`theme-color` も資料側で light / dark の2本を出す）。
  「ダークモードが効かない」は不具合ではなく、この例外の帰結。
- レビューで「色が `theme.css` に集約されていない」という指摘が `lt/` 配下に出たら、
  この行を根拠に据え置いてよい。**撤回するときは、この行とルート `CLAUDE.md` の
  ファイル表の `lt/` の行の両方を直す**（2箇所に書いてある）。

### 掲載前の棚卸し 🔴

会場で話したことと、サイトに恒久掲載することは別。**取り込むたびに資料を1枚ずつ確認する。**

0. 🔴 **棚卸しは最初のコミットの前に済ませる。** 「取り込んでから直す」と、直す前の内容が
   **公開リポジトリの履歴に残る**（push 後は force-push しても GitHub 上は SHA 指定で
   到達可能なまま。ルート `CLAUDE.md` の所在地節 手順6と同じ論点）。
   ローカルで 1〜6 を通してから最初のコミットを作ること。
   ※ 2026-09-12 に実際に発生: 一次資料未確認の企業名と人数を含む版をコミットしてしまった。
1. **受託業務に触れる記述**（客先名・案件の説明における業界名・規模を示す語・
   案件を特定し得る表現）— 必須ルール1。自作の資料であっても、
   **情報の出所が案件なら秘密保持の対象**であることに変わりはない。
   自己紹介は `about.html` の言い回しに揃えるのが安全。
2. **委託元に著作権のある成果物**（要件定義書・設計書・図・画面）— 必須ルール2
3. **契約書の文言・条項番号**— 必須ルール3
4. **数値と出典** — 必須ルール4。**一次資料を読めていない数値は載せない。**
   料金・無料枠のように改定されるものは、**いつ時点のものか**が分かるように書く
   （現在形は現況と誤読される）。
5. **協働先の社名** — 確認済み事項「パートナー企業との協働」の 🔴
6. 🔴 **第三者の氏名・肖像・発言・著作物** — 契約とも自主ルールとも別の、第三者の権利。
   会場で映すことと、**営業サイトに置き続ける**ことは性質が違う。写真を消せば済む話ではない。
   - 肖像・著作物は**許諾がないものを載せない**（2026-09-12 に1件、埋め込み画像を削除した）
   - 実在の個人が主題になる資料は、**提携・監修・後援の関係がない旨の注記**を本文に置く
   - 人名を `meta description`・OGP・JSON-LD・`llms.txt` など**検索面に出さない**
     （本文に置くことと、人名クエリで当社ページが出ることは別）
   - **引用が主にならないようにする**（当社の論考が主、引用が従）。
     第三者の発表内容の詳細な再構成が大半を占めるなら、一次情報へのリンクで代替する
   - 個人的な言及（「推し」等）は残さない
   - 第三者の**将来の予定**を現在形で恒久掲載しない（時点を明記するか落とす）

### 外部リンク

- 資料が拠り所にした**出典へのリンクは残してよい。ただし必須ルール4の条件を満たすこと**:
  - 🔴 **読んでいないURLを出典として貼らない**（検索要約とリンクを結びつけない）
  - 🔴 **出典は記述ごとに対応させる。** スライド末尾に出典欄を置き、**URLと参照日**を書く。
    複数の出典を束ねて複数の記述に掛けない
  - 🔴 **一次資料が公開されているもの**（料金ページ・公式発表など）は**一次資料を出典にする**。
    二次情報しか当たれていない数値は載せない
- 🔴 **出典以外の外部リンク（人物・ブログ・SNS の紹介リンク）は足さない。**
  すでにあるものは、出典として使っていないなら落とす。
- **CraftStage の個別イベントページ・代表個人の SNS へのリンクは足さない**
  （確認済み事項「技術コミュニティ CraftStage への関与」の 🔴）。ここは出典ではなく
  裏づけリンクの話なので、上の例外に含めない。
- `target="_blank"` には必ず `rel="noopener"`（ルートの規約・CI が検査する）。

### 会の名前

- **CraftStage は主催団体、AILT会 はその会の名前**（所有者確認 2026-09-12。ルートの
  確認済み事項に記録がある）。**資料が会の名前で書かれているのは表記のずれではない。**
- サイト本文の7箇所は主催団体名で書かれている。**この配下の資料は、その7箇所の
  同期対象には含めない**（関与の書き方ではなく、当日の記録のため）。
