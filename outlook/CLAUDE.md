# outlook/CLAUDE.md — 「今後の展望」セクション

ルートの `CLAUDE.md`（必須ルール・開発フロー）に加えて、**outlook 配下だけに適用される**ルール。

## 大原則

- 公開URLは `/outlook/…`（拡張子なし。ディレクトリ index 方式）。
- **配下は全ページ noindex 運用**（`<meta name="robots" content="noindex, follow">`、
  sitemap にも載せない）。検討中コンテンツを検索結果に出さないため。新ページも同様にする。
- 語り口は**「検討中・考えている」**を保ち、提供中のサービスと誤認される断定表現を避ける
  （各ページ冒頭に「検討中であり提供中のサービスではない」旨の注記あり。景表法配慮）。
- 更新時は JSON-LD の `dateModified` と可視の「最終更新」表記を更新する。
  検討テーマが変わったら `llms.txt` の「今後の展望」も同期する。
  **sitemap 非掲載のため lastmod 同期は不要。**
- 数字や成果が出たテーマは独立ページに切り出す（切り出したら sitemap・ナビを更新）。

## 階層モデル

`outlook/`（ジャーナル＋テーマ一覧）→ `/outlook/テーマ`（ハブ）→ `/outlook/テーマ-○○`
（企画案・記録）→ そのデモ、の**最大4階層**。GX（`gx` → `gx-pipeline` → `gx-pipeline-demo`）が
参照実装。

- 各テーマは**サービスに結びつく出口**（プロトタイプ・デモ・商品化の種）を意識して育てる。
- **デモページの命名は「親スラッグ-demo」**（例: `gx-pipeline` の子デモ → `gx-pipeline-demo`）。
- 単一ページのテーマ（local / academics / sports）も、育ったら同じ型でハブ化して子をぶら下げる。
- 旧URL `/outlook/gx-demo` はリダイレクトスタブ（`outlook/gx-demo.html`、noindex）。
  **編集・削除しないこと。**

## ジャーナル（`outlook/index.html`）の運用

- 新しいエントリは `.entries` の**一番上**に `<article class="entry">` で追加（新しい順）。
  **同じ日の関連する話題は原則1つのエントリにまとめる**（分ける場合は
  上から読んで自然な順＝出来事→考察に並べる）。
- 構造はアコーディオン（JS不要の `<details class="entry-details">`）。
  `<summary>` に `<h2>` タイトル＋`<span class="entry-toggle">`、本文は
  `<div class="entry-body">` 内の `<p>`。日付とタイトルのみ常時表示、本文は閉じた状態がデフォルト。
- 追記のたびに既存エントリも含めて**文章を推敲**する（重複表現・冗長な言い回し・
  同じ語の繰り返しを削る。**意味を変える書き換えは行わない**）。

## 新しいテーマページを作るとき

- **5点セットで更新**する:
  ① `outlook/nav.js` の THEMES（ハブ配下なら `children` も）
  ② index の `.topics` 一覧
  ③ index の JSON-LD `hasPart`
  ④ ハブのテーマカードと `hasPart`（ハブ配下のページの場合）
  ⑤ **サイト全体のグローバルナビの子項目**（`site.css` を使う7ファイルの `#nav-sub-outlook`）。
    ここに出すのは**トップレベルのテーマだけ**で、ハブ配下の子（`gx-pipeline` 等）は出さない
    （① の THEMES の `children` とは粒度が違う）。
    **① の「ジャーナル」だけは出さない**。親の「今後の展望」が同じ `/outlook/` を指しており、
    同一URLへのリンクが隣り合って重複するため（① では親がリンクでないので必要）
- **`theme.css` と `outlook.css` の両方を読み込む**（片方だけだと回遊ナビが未装飾で出る）。
- `<body>` 直後に `.reading-progress` の1行を入れる。
- **章立て**: 「**このテーマについて**」（そのページが何かを一段落で。必須）→ テーマ固有の本編 →
  「これから取り組むこと」「現在地」など現状の位置づけ → 「**参考資料**」（出典がある場合のみ）→
  「**共創のご縁を探しています**」（CTAなので必ず最後）。
  単一ページのテーマは本編の代わりに「考えていること（すべて検討中）」＋「現在地」でよい。
- **構造化データ**: index は `CollectionPage` ＋ `hasPart`、配下ページは `isPartOf` ＋
  `BreadcrumbList`。見えるパンくず（`.crumbs`）と「← 今後の展望へ」ナビで統一する。
  例外: GX系はハブ `gx` の下に階層化しており、`gx-pipeline` / `gx-decokatsu` のナビは
  「← GX構想へ戻る」・`isPartOf` は `gx`、`gx-pipeline-demo` のナビは「← 前工程構想へ戻る」・
  `isPartOf` は `gx-pipeline` を指す。

## スタイル（`outlook/outlook.css`）

`theme.css` の後に読み込む。ページ共通の土台（body・nav・`.crumbs`・`.concept-*`・footer・
レスポンシブ／モーション低減のメディアクエリ）は本ファイルにあるので、**新しいページで
これらをインラインに書き直さない**（2026-07-30 に各ページの重複インラインCSS 約1,700行を
集約済み。ページの `<style>` には固有の指定だけを置く）。

- `nav { position: fixed }` も本ファイルにあるため、outlook 配下で新たに `<nav>` 要素を足すと
  意図せず固定配置になる（`nav.js` が `div` ＋ `role="navigation"` を使っているのはこのため）。
- 色は `theme.css` のカスタムプロパティのみ参照する。
- 本セクション限定のモダンCSS拡張も本ファイルに集約する:
  `::details-content` ＋ `interpolate-size`（アコーディオンの高さアニメーション）、
  `:has()`（開いているエントリの強調）、`animation-timeline: view()`（エントリの立ち上がり・
  ジャーナル縦線の伸長）、`@property`（下線アニメーション）、`view-transition-name`
  （ページ間の連続性）、`text-wrap: pretty`、`word-break: auto-phrase`（中見出しの文節改行。
  `text-wrap: balance` を指定した要素では効かないため、balance を使うタイトル・エントリ見出しは
  対象外）、`animation-timeline: scroll(root block)`（読書プログレスバー）、`::target-text`、
  コンテナクエリ、`@starting-style` ＋ `sibling-index()`（順次表示）、`field-sizing`。
- **すべて `@supports` と `prefers-reduced-motion` でガード**し、非対応環境では従来表示に
  フォールバックさせる。**内容が見えなくなる実装は禁止。**

### 差し色（藍）── セクション全体の色調

「今後の展望」は検討中の思考を置く場所なので、コーポレート本体（紅系）とは**一目で分かる程度に
空気を変えている**。実装は `outlook.css` 冒頭の `:root` ブロックで、theme.css のアクセント系
トークンを本セクションだけ藍系に**丸ごと差し替える**方式:

| 差し替えるトークン | 参照先（theme.css の藍系） | 効く場所の例 |
|---|---|---|
| `--accent` | `--accent-cool-deep` | ホバー、選択範囲、強調 |
| `--accent-gold` | `--accent-cool` | 区切り線、見出しの罫、箇条書きの点、リンク、日付、タイムライン、バッジ |
| `--accent-pale` | `--accent-cool-pale` | ボタンのホバー背景 |
| `--ring` | `--ring-cool` | 影の色（現状 outlook では未使用。カード影を足したとき揃うよう予約） |
| `--paper` | `--paper-cool` | 地の紙色（寒色寄りの白。本体の温かいクリーム色と対比） |
| `--nav-bg` | `--nav-bg-cool` | 固定ナビの半透明背景（紙色と揃える） |
| `--paper-mid` | `--paper-cool-mid` | パネル・カードの下地 |
| `--paper-dark` | `--paper-cool-dark` | 罫線・境界 |
| `--sakura-deep` | `--accent-cool-mid` | 概算グラフの3系統の描き分け |

- **個々の要素に `--accent-cool` を直接指定しないこと。** 標準トークン（`--accent-gold` 等）を
  使えば自動的に藍になる。新しいページ・要素を足しても色調が揃うのはこの仕組みのため。
- **文字色（`--ink` 系）は変えない。** 紙色は寒色寄りの白に振るが、明度は本体とほぼ同じに保ち、可読性を落とさない。
- 色調を調整したいときは theme.css の藍系トークンの値を変えれば、セクション全体に反映される。

## 回遊ナビ（`outlook/nav.js`）

配下全ページのテーマ間ナビを `.crumbs` 直後に注入する（JS無効時はパンくず＋ハブ経由が残る）。
見た目は `outlook.css` 側が持つ。2段構成で、1段目がテーマ一覧（THEMES）、2段目は `children` を
持つテーマの配下にいるときだけ出る兄弟ページ一覧（`.outlook-subnav-child`）。
2段目の現在地は最長一致で決まるため、デモページでは親テーマが選択状態になる。

## noindex の段階解除方針

2026-07 決定。現状は全ページ noindex だが、AI検索には `robots.txt` / `llms.txt` で開いている。
**「実態が先、公開はそれに追いつく」**が原則。

- **フェーズ1**: `gx-pipeline-demo` の原単位が公的DBの実数値に置き換わったら（概算が参考値から
  一段上がったら）、**事実・ツール系ページ**（`gx-pipeline-demo`、`academics` の学びの記録、
  `gx-decokatsu`）の noindex を解除して sitemap に追加する。解除開始前に
  Google Search Console を登録し、効果測定できる状態にする。
- **フェーズ2**: サービス化を決めたテーマは、構想ページ（`gx-pipeline` 等）を正式ページに
  昇格させて index する。
- **ジャーナル（`/outlook/` 本体）と未成熟の構想ページ**（local / sports 等）は当面 noindex 維持。
  柔らかい思考置き場を検索から守る弁のため。
- 解除時の作業: `meta robots` 変更 → sitemap 追加（lastmod 同期）→ 検索流入者が文脈なしで読む
  前提で文言を再点検 → content-legal-review 通過後にマージ。
